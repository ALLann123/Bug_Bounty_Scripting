=========AUtomation in Bug Bounty===========
- Automation doesnt find bugs. 
	`Automated workflows combined with manual validation`
- Workflow pipelines:
	> Monitor 1000+ targets
	> Detect configuration changes in real time
	> Alert attacker when high-alert vulnerabilities emerge.


========Workflow Overview=========
1. Automation
2. Money Growth
3. Time
4. Human Validation
- Automation alone wont make you rich: Top hunters use automation for reconnaissance
and continuous monitoring, but manual analysis find high-value bugs.
- Complete stack costs $0-50/month: All tools are open source; infrastrucute costs
are your only expense(VPS, Cloud computing)
- Realistice earnings timeline: Months 1-6 building the system($0 earned,
Months 7-18 optimizing workflows($100-500/month), Year 2+ with mature system
($10,000-10,000+/month)
- The 60/40 rule: Successful hunters automate 60% of reconnaissance and monitoring, spend
40% on manual testing and validation.
MINDSET: Automation finds opportunities; humans find vulnerabilities.

2. Amass(OWASP Project)
- Tool is used for asset discovery and network mapping.
- Identifys:
	> subdomains
	> perform DNS enumeration
	> Visualize relationships between discovered assets to asses potential vulnerabilities
- Installation:
	kali> go install -v github.com/owasp-amass/amass/v4/...@master

	kali> amass enum -passive -d example.com -config ~/.config/amass/config.ini -o amass_out.txt
- Active enumeration(when in scope):
	kali> amass enum -active -d example.com -brute -w wordlist.txt -o amass_active.txt

============Layer 3: Asset Probing & Discovery================
Tools:
1. httpx(ProjectDiscovery)
- Installation:
	kali> go install -v github.com/projectdiscovery/httpx/cmd/httpx@latest
- Basic probing:
	kali> cat sudomains.txt | httpx -silent -o live_hosts.txt
- Advanced: Get titles, status codes, tech stack
	kali> cat subdomains.txt | httpx -silent -title -status-code -tech-detect -follow-redirect -o httpx_results.txt
- Screenshot capabilities:
	kali> cat sudomains.txt | httpx -silent -screenshot -o screenshots/

2. httprobe(tomnomonom)
- Takes a list of domains and probe for working http and https servers.
- Install:
	kali> go install github.com/tomnomnom/httprobe@latest
	kali> sudo cp ~/go/bin/httprobe /usr/local/bin/
Usage:
	kali> cat subdomains.txt | httprobe -c 50 > live_urls.txt
Pro tip: httpx is more feature-rich and actively maintained. 
- It can detect technologies(wappalyzer-style) and extract useful metadata in
one pass.



============Laye 4: Content Discovey & Crawling==============
Tools:
1. Katana(ProjectDiscovery)
- Is a web crawler. Useful for hunting hidden endpoints
- Web Crawling, referes to the process of automatically navigating through a
website's structure to discover various resources such as web pages, files and
scripts. 
Done by following links and examining directories to create a map of a websites
content. 
- Installation:
	kali> go install github.com/projectdiscovery/katana/cmd/katana@latest
	kali> export PATH=$PATH:$(go env GOPATH)/bin
- Crawl wth depth:
	kali> katana -u https://example.com -d 5 -jc -kf all -o katana_results.txt
- Crawl multiple URLs
	kali> cat live_urls.txt | katana -d 3 -jc -aff -o crawled_endpoints.txt

2. waybackurls
- CLI tool that allows attackers to fetch historical URLs of a website from the
wayback machine.
- Install:
	kali> go install github.com/tomnomnom/waybackurls@latest
- Crawl with depth:
	kali> echo "example.com" | waybackurls > wayback_urls.txt

3. gau(GET ALL URLS)
- Installation:
	kali> go install github.com/lc/gau/v2/cmd/gau@latest
- Aggregate URLs from multiple sources:
	kali> echo "example" | gau --blacklist png, jpg, gif, css --threads 5 > gau_urls.txt

4. hakrawler(hakluke)
- Web crawler for gathering URLs and JS file locations.
	kali> echo "https://example.com" | hakrawler -depth 3 -plain -usewayback -o hakrawler_out.txt

Why it matters: 
`A hunter analyzed that combining waybackurls, gau and active crawling with
katana can reveal 3-5x more endpoints that crawling one alont.`
- Can reveal endpoints from 2019? still accessible and often unpatched.


==========Layer 5: JavaScript Analysis============
1. LinkFInder(GerbenJavado)
- Discoveres endpoints and their parameters in JavaScript files.
- ALlows bug hunters to gather hidden endpoints in the websites they are testing
- Resulting in a new testing ground, possibility containing new vulnerabilities
GET TOOL:
- Git Clone:
	kali> git clone https://github.com/GerbenJavado/LinkFinder.git
	kali> cd LinkFinder
- Create a python virtual environment:
	kali> python -m venv venv
- Activate:
	kali> source venv/bin/activate
	kali> pip3 install -r requirements.txt
- Find endpoints in JS files
	kali> python3 linkfinder.py -i https://example.com/app.js -o results.html

2. JSFinder
- More faster that previous tool, written in golang
- Scans web sites to find JavaScript files linked in the HTML source code.
- Extratcs the URLs of the files to text file.
- By analyzing the files discovered its possible to understand the functionality
of the application and detect any security vulnerabilities or sensitive information
leakage.
	kali> go install -v github.com/kacakb/jsfinder@latest
	kali> export PATH=$PATH:$(go env GOPATH)/bin
	kali> jsfinder -h
- Usage:
	kali> echo https://example.com | jsfinder -read -s -o js.txt

3. SecretFinder
- Python script based on linkFinder.
- Discovers sensitive data like:
	> apikeys
	> accesstoken
	> authorization
	> jwt
	> Js Files
- Install:
	kali> git clone https://github.com/m4ll0k/SecretFinder.git
- Set up python virtual environment:
	kali> python -m venv venv
	kali> source venv/bin/activate
- Install tool requirements:
	kali> pip3 install -r requirements.txt
- Find API keys and tokens in JS files:
	kali> python3 SecretFinder.py -i https://example.com/app.js -o secrets_output.html

====REAL-WORLD Impact======
- One researcher found AWS keys exposed in JavaScript files that led to full s3
bucket access -- $15000 bounty. 
- JS analysis is often overlooked by automated scanners.



===========Layer 6: Vulnerability Scanning==================
1. Nuclei(Project Discovery)
- Customized vulnerability scanner that uses YAML-based templates to identify security
issues across applications, networks and cloud configurations.
- Supports over 6 protocols enabling targeted scanning for:
	> CVE's
	> Misconfigurations
	> Subdomain takeovers
- Can be added to CI/CD security intergration.
- Installation:
	kali> go install -v github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
- Add:
	kali> export PATH=$(go env GOPATH)/bin:$PATH
- Update templates:
	kali> nuclei -update-templates
- Basic Scan:
	kali> nuclei -l live_urls.txt -o nuclei_results.txt
- Severity-based Scanning:
	kali> nuclei -l live_urls.txt -severity critical,high -o critical_bugs.txt
- Custom templates:
	kali> nuclei -l targets.txt -t ~/nuclei-templates/custom/ -o custom_scan.txt
PRO CONFIGURATIONS:
	- Create custom workflows with high-value templates
*******************************************************
kali> # Focus on misconfigurations and exposures
nuclei -l urls.txt \
  -t nuclei-templates/exposures/ \
  -t nuclei-templates/misconfiguration/ \
  -t nuclei-templates/vulnerabilities/ \
  -severity high,critical \
  -o high_value_findings.txt
*******************************************************
- If no templates were loaded go and gitclone the repository:
	kali> mkdir -p ~/.local/share
	kali> cd ~/.local/share
	kali> git clone https://github.com/projectdiscovery/nuclei-templates
